# x402 PostgreSQL schema rollout (manual, not yet applied)

This SQL is a reviewed rollout artifact for the two x402 tables added to
`prisma/schema.prisma`. It is intentionally kept outside
`prisma/migrations`: this repository has no existing Prisma migration
history, so introducing a partial migration history must be planned separately.

## Preconditions

- Confirm the target is the intended Arc Testnet application database.
- Take and verify a restorable database backup.
- Compare the target schema with the current Prisma schema and check that these
  table names do not already exist.
- Schedule a maintenance window and have an operator with database access run
  this SQL manually.
- Do not use `prisma db push` as a substitute for this reviewed rollout.
- Do not run against production until the owner explicitly approves the
  database change.

## Apply

Run the whole script as one transaction. PostgreSQL identifiers are quoted to
match Prisma's default model and field naming. Prisma's `cuid()` values are
generated by the Prisma client, so the id columns intentionally have no
database-side default.

```sql
BEGIN;

CREATE TABLE "X402Payment" (
  "id" TEXT NOT NULL,
  "txHash" TEXT NOT NULL,
  "payer" TEXT NOT NULL,
  "recipient" TEXT NOT NULL,
  "token" TEXT NOT NULL,
  "amount" TEXT NOT NULL,
  "chainId" INTEGER NOT NULL,
  "blockNumber" TEXT NOT NULL,
  "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT "X402Payment_pkey" PRIMARY KEY ("id")
);

CREATE UNIQUE INDEX "X402Payment_txHash_key"
  ON "X402Payment"("txHash");
CREATE INDEX "X402Payment_payer_idx"
  ON "X402Payment"("payer");
CREATE INDEX "X402Payment_createdAt_idx"
  ON "X402Payment"("createdAt");

CREATE TABLE "X402Challenge" (
  "id" TEXT NOT NULL,
  "nonce" TEXT NOT NULL,
  "serviceId" TEXT NOT NULL,
  "chainId" INTEGER NOT NULL,
  "token" TEXT NOT NULL,
  "recipient" TEXT NOT NULL,
  "amount" TEXT NOT NULL,
  "expiresAt" TIMESTAMP(3) NOT NULL,
  "consumedAt" TIMESTAMP(3),
  "createdAt" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT "X402Challenge_pkey" PRIMARY KEY ("id")
);

CREATE UNIQUE INDEX "X402Challenge_nonce_key"
  ON "X402Challenge"("nonce");
CREATE INDEX "X402Challenge_serviceId_expiresAt_idx"
  ON "X402Challenge"("serviceId", "expiresAt");
CREATE INDEX "X402Challenge_expiresAt_idx"
  ON "X402Challenge"("expiresAt");

COMMIT;
```

## Verify after apply

1. Confirm both tables, all columns, nullability, and timestamp precision.
2. Confirm unique indexes on `X402Payment.txHash` and `X402Challenge.nonce`.
3. Confirm the four non-unique indexes listed above.
4. Run Prisma schema validation and a read/write integration test against a
   disposable database first. Do not create a real payment.
5. Only after a separate security review should the endpoint be considered for
   activation. A successful schema rollout alone does not enable payments.

## Rollback

Only if no application traffic has written x402 rows and the operator has
confirmed the tables contain no data, execute:

```sql
BEGIN;
DROP TABLE "X402Challenge";
DROP TABLE "X402Payment";
COMMIT;
```

If either table contains data, do not use this rollback. Preserve the records
and prepare a data-aware rollback plan instead.
